## Что умеет кабинет

**Студент (в первую очередь телефон, от 360 px):**
- главная - три больших числа дня: время до следующей пары, проверка в Антиплагиате, средний балл;
- расписание на день и неделю, переносы и смены аудиторий выделены; на компьютере - сетка недели;
- **подписка календаря телефона одной кнопкой:** переносы приходят в календарь сами (частная ссылка `.ics`);
- оценки, сессия, Антиплагиат, Moodle, документы, вопросы в деканат, новости;
- заявки и справки: заказ в три касания и статус заявки;
- уведомления (колокольчик) о переносах, статусах заявок, оценках и новостях;
- дневная и ночная тема.

**Деканат:** четыре числа на главной (заявки, вопросы, изменения сегодня, справки к выдаче); очередь заявок;
справка в PDF из данных студента одним нажатием; перенос или отмена занятия с причиной - студенты получают
уведомление; сетка недели по группам; карточка студента: изменение оценки с обязательной причиной,
уважительные пропуски.

**Преподаватель:** занятия на сегодня и неделю, посещаемость («Был / Опоздал / Нет»), журнал оценок - новая
оценка сразу видна студенту, импорт оценок из Excel.

## Как устроены вход, данные и защита (простыми словами)

- **Пароли** хранятся только в виде хэша argon2id - восстановить пароль из базы нельзя.
- **Вход:** после входа браузер получает случайный ключ сессии (256 бит) в cookie `httpOnly`, `Secure`,
  `SameSite=Lax`; в базе лежит только его SHA-256. Сессия живёт 8 часов. После 5 неудачных попыток вход
  по этому логину блокируется на 15 минут.
- **Каждый видит только своё.** Любой запрос к базе начинается с проверки сессии внутри того же SQL-запроса.
  Подставить в адрес чужой номер заявки или документа бесполезно: ответ такой же, как для несуществующей
  страницы. Деканат видит только свой факультет, преподаватель - только свои группы.
- **Ключей в коде нет.** Пароль базы задаётся на сервере в `.env` и не попадает в репозиторий и в браузер.
  ИИ-сервисы в работающем приложении не используются.
- Проверка: `npm run smoke` - 64 автоматические проверки, включая попытки открыть чужие данные (IDOR) и
  действия чужой роли.

## Технологии

Next.js 16 (App Router, серверные компоненты и server actions), React 19, PostgreSQL 16 (`pg`),
argon2 (`@node-rs/argon2`), pdf-lib для справок, Docker Compose и Caddy (HTTPS) на VPS в России.
Формы - обычные `<form>`, поэтому основные сценарии работают и без JavaScript.

```
браузер ── Next.js
            app/(student)/   кабинет студента
            app/staff/       деканат        app/teacher/   преподаватель
            app/cal/[token]  частная ссылка календаря (.ics)
            lib/dal/*        чтение: каждый запрос авторизуется сессией в SQL
            lib/changes/*    запись: авторизация в той же транзакции + уведомления
        ── PostgreSQL        db/001-015 (база Codex), db/100-104 (наши миграции)
```

## Запуск у себя

Нужны Node.js 22+ и Docker.

```sh
cp .env.example .env
docker compose up -d --wait db     # PostgreSQL 16 на 127.0.0.1:5433
npm ci
npm run db:setup                   # применяет db/*.sql по одному разу и включает тестовые аккаунты
npm run build && npm run start     # http://localhost:3000
BASE_URL=http://127.0.0.1:3000 npm run smoke
```

## Развёртывание на сервере

`deploy/` - всё, что нужно для VPS (Ubuntu 24.04, Docker): `compose.server.yaml` (приложение, база, Caddy с
бесплатным сертификатом Let's Encrypt), `Caddyfile`, `daemon.json` (зеркало Docker Hub - из России Docker Hub
отвечает ошибкой 429) и `redeploy.sh` (копирует код, пересобирает, применяет миграции, перезапускает).
Пароль базы создаётся на сервере в `.env` с правами 600.

## Ключевые решения

1. **Главная отвечает на вопрос «что у меня сегодня?»** тремя большими числами, а не меню из 15 разделов:
   студенты в основном пользуются расписанием, оценками, Антиплагиатом и Moodle.
2. **Стиль «Большие цифры + Угол»** выбран из нескольких концептов (сферы, папки, орбита): он строгий,
   быстрый и не выглядит как типичный сайт, сделанный ИИ.
3. **Сервер в России** вместо Vercel: `*.vercel.app` не открывался без VPN у Tele2 и Билайна (проверка 7 ноября).
4. **Безопасность в одном слое данных:** ни один запрос не идёт в базу без сессии.
5. **Две ИИ-команды:** базу данных, вход и слой доступа написал Codex (вторая команда агентов), интерфейс,
   кабинеты сотрудников и развёртывание - Claude Code. Агенты проверяли работу друг друга в общем репозитории.

## Что имитируется

- Антиплагиат не читает файл: сохраняется только имя, процент вычисляется детерминированно.
- Moodle, ЭБС и скачивание документов показывают сообщение, а не открывают внешние системы.
- Уведомления приходят внутри кабинета (колокольчик); почта и push не отправляются.
